# Testing - Layer 1: Network and Operations

**Scope:** The dedicated network and operational services of the testing environment in the non-production subscription. There is no peering to the development network.

**Lifecycle:** Created after layer 0 and before layer 2; removed after layer 2. The NAT public address and the flow log storage live in layer 0 and survive a removal.

**Status: Built and run by its pipeline.** `sits-infra-test-l1` (`pipelines/infra-test-l1.yml`, identity `test-infra-l1`, Microsoft-hosted agent) plans, applies only when there are changes, and verifies that a second plan reports no changes. The state is stored in `stsitstftestswc`, container `tfstate-layer1`. Build records: [10](../../../../docs/build-log/10-testing-environment.md) and [12](../../../../docs/build-log/12-monitoring-alerts-and-infrastructure-pipelines.md).

## Contents

| File | Resources |
| --- | --- |
| `main.tf` | Virtual network 10.20.0.0/16 with six subnets (gateway, private endpoints, App Service integration, Ops VM, infrastructure agents, application agents) |
| `nsg.tf` | Network security group per subnet ending with Deny at priority 4000, application security groups |
| `nat.tf` | NAT Gateway with the permanent address from layer 0 |
| `dns.tf` | Private DNS zones for Key Vault, Web Apps, and `test.sits.internal`, linked only to this network |
| `pe.tf` | Private endpoints to the certificate and admin vaults of layer 0 |
| `ops.tf` | Windows Ops VM (local administrator password generated by Terraform) and Azure Bastion Developer |
| `flowlogs.tf` | VNet flow log with Traffic Analytics into the shared non-production workspace |
| `managed-devops-pools.tf` | Dev Center, project, and two stateless Managed DevOps Pools (Standard_D2as_v5 because of the regional quota) |

## Usage

Normally run through `sits-infra-test-l1`. A local run with the Lab Admin account works while `temporary.tf` in layer 0 grants the state role:

1. Copy `testing.example.tfvars` to `testing.tfvars` and fill in the real values. The file is ignored by Git.
2. `terraform init`
3. `terraform plan -var-file="testing.tfvars" -out="tfplan"`, review, then `terraform apply "tfplan"`; a second plan must report no changes.

The Ops VM password is available with `terraform output -raw ops_vm_admin_password`; it is stored in the state.
